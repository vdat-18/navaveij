# Navaveij Clinical MCP Server

This server provides a standardized, read-only interface to pre-computed clinical signals and medical rules for the Navaveij Health Checkup Recommendation system.

## Overview

The MCP Server acts as a secure data bridge between raw patient data/clinical rules and the AI inference engine. It adheres to the **Model Context Protocol (MCP)** and enforces the **Least Privilege** principle.

## Project Structure

- `server.py`: Main entry point and tool registration.
- `utils.py`: Utility functions for loading Signal Store and Ruleset Store data.
- `tools/`: Individual tool implementations.
  - `hard_constraints.py`: Gender/Age-specific medical constraints from Signal Store.
  - `clinical_signals.py`: Risk alerts and abnormality triggers from Signal Store.
  - `biomarker_trends.py`: Historical data and velocity from Signal Store.
  - `program_ruleset.py`: Business rules for checkup tier selection from Ruleset Store.

## Core Tools

| Tool | Purpose | Parameter | Returns |
|------|---------|-----------|---------|
| `get_patient_context` | Demographic & identity info | `patient_id` | `{"name": "...", "age": 54, ...}` |
| `get_hard_constraints` | Non-negotiable medical rules | `patient_token` | Signal Store Contract format |
| `get_clinical_signals` | Risk flags and alerts | `patient_token` | Signal Store Contract format |
| `get_biomarker_trends` | Historical trend analysis | `patient_token` | Signal Store Contract format |
| `get_program_ruleset` | Package mapping logic | `patient_token` | Ruleset Store Contract format |

## Breaking Changes

**⚠️ Important:** All Signal Store tools now require `patient_token` (HMAC-SHA256 pseudonymous identifier) instead of `patient_id`. This matches the Signal Store Contract specification.

If you need to map from `patient_id` to `patient_token`, you must implement the HMAC-SHA256 hashing logic as specified in the contract.

## Data Sources

- **Signal Store**: Reads from `src/mcp_server/data/synthetic/signal_store_*.json` files (generated by synthesis orchestrator)
- **Ruleset Store**: Reads from sample JSON files:
  - `doc_outputs/architecture/AI/Recommendation Engine/v3/samples/sample_ruleset_tier_config.json`
  - `doc_outputs/architecture/AI/Recommendation Engine/v3/samples/sample_add_on_items.json`

## Response Formats

All tools return data matching the exact JSON Schema defined in:
- `doc_outputs/architecture/AI/Recommendation Engine/v3/schema-contracts/signal-store-contract.md`
- `doc_outputs/architecture/AI/Recommendation Engine/v3/schema-contracts/ruleset-store-contract.md`

## Usage

### Prerequisites
- Python 3.10+
- [uv](https://docs.astral.sh/uv/) (Recommended)
- Dependencies: `mcp`, `loguru`, `pydantic`

### Installation
```bash
uv sync
```

### Running the Server
To run the server in `stdio` transport mode (standard for local testing):
```bash
# Using module mode (Recommended)
PYTHONPATH=. uv run python -m src.mcp_server.server

# Or using script mode
PYTHONPATH=. uv run python src/mcp_server/server.py
```

### Testing with MCP Inspector
The best way to test the tools visually is using the official MCP Inspector:
```bash
PYTHONPATH=. npx -y @modelcontextprotocol/inspector uv run python src/mcp_server/server.py
```
After running, open the provided URL in your browser and click **Connect**.

## Coding Standards

- **Formatting**: Checked and formatted via [Ruff](https://beta.ruff.rs/docs/).
- **Validation**: Inputs and outputs are strictly validated using **Pydantic v2** models in `src/shared/schemas.py`.
- **Logging**: Uses `loguru` for structured audit logs. No `print` statements allowed.
- **Docstrings**: Concise Google-style docstrings for all classes and functions.
