## GAP-UI-14 — Accessibility implementation plan

### Scope to implement
1. Add `aria-current="page"` on active sidebar link.
2. Add `aria-label="Main navigation"` on sidebar landmark container.
3. Add `aria-label="Search patients"` on patient search input.
4. Replace sidebar logo `<img>` with Next `<Image>` and explicit size.
5. Add a root-level error boundary and wrap layout children with it.

### Design options
**Option A (Recommended): Error boundary class component**
- Implement `components/ErrorBoundary.tsx` as a class boundary.
- Keep fallback minimal and non-destructive (error notice + retry hint).
- Wrap only route content area so navigation remains available.

**Option B: Route-level `error.tsx` only**
- Use Next route segment error pages instead of a reusable boundary.
- Lower component reuse and weaker protection for client-tree subtrees in shared layout.

Proceed with **Option A**.

### Files to change
- `src/components/Sidebar.tsx`
- `src/components/dashboard/PatientList.tsx`
- `src/components/ErrorBoundary.tsx` (new)
- `src/app/layout.tsx`

### Acceptance criteria
- Active nav link exposes `aria-current="page"`.
- Sidebar has explicit navigation landmark label.
- Patient search input has accessible name.
- Sidebar logo uses Next `Image` with stable dimensions.
- Runtime rendering exceptions inside content tree are caught by boundary fallback.

## GAP-UI-15 — Test coverage implementation plan

### Test setup scope
1. Install and configure Vitest + RTL + jsdom stack.
2. Add `vitest.config.ts` and test setup file with `@testing-library/jest-dom`.
3. Add package scripts: `test`, `test:watch`, `test:coverage`.

### Test implementation scope
1. `RecommendationPanel.test.tsx`
   - No fabricated alerts on empty/unexpected response.
   - Risk gauge label behavior for High/Medium/Low/Critical.
   - Approval call uses dynamic physician context path (post GAP-UI-4 behavior).
2. `PatientList.test.tsx`
   - API failure renders error state, not empty-list state.
3. `AuditLogSearchPanel.test.tsx`
   - HTTPS warning appears when `crypto.subtle` is unavailable.
4. `Sidebar.test.tsx`
   - Active route renders link with `aria-current="page"`.

### Design options
**Option A (Recommended): Component-level unit/integration tests with service mocks**
- Mock `@/services/api` and `next/navigation`.
- Focus deterministic UI behavior and guardrails.

**Option B: Browser E2E first**
- Add Playwright/Cypress now.
- Higher setup cost and runtime volatility for this phase.

Proceed with **Option A**, with optional E2E expansion in a later wave.

### Files to add/update
- `package.json`
- `vitest.config.ts` (new)
- `src/test/setup.ts` (new)
- `src/components/dashboard/RecommendationPanel.test.tsx` (new)
