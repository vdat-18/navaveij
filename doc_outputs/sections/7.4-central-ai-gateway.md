# 7.4 Central AI Gateway

The Central AI Gateway is a dedicated routing and abstraction layer that sits between the clinical application and all external LLM providers. Its purpose is to ensure that the clinical agent pipeline has no direct dependency on any specific AI provider — model selection, fallback behaviour, timeout enforcement, and credential management are all handled at the gateway layer, invisible to the application code above it.

### Responsibilities

**Provider abstraction.** Clinical agents issue inference requests through a single, stable interface. The underlying model — whether from a cloud AI lab, an open-source deployment, or an on-premise server — is resolved at runtime by the gateway. No provider-specific client code exists in the application layer.

**Automatic fallback chain.** The gateway maintains an ordered list of model candidates. If the configured primary model is unavailable, times out, or returns an unrecoverable error, the gateway automatically retries with the next candidate in the chain. This process is transparent to the clinical agent — the agent receives a valid response or a clean failure, never a partially-handled provider error.

**Per-call timeout enforcement.** Every inference call is subject to a maximum wall-clock timeout, configured at the gateway level. This bounds worst-case latency regardless of provider behaviour and prevents a slow or unresponsive model from blocking the recommendation pipeline.

**Credential isolation.** Provider API keys are managed via environment configuration and are never referenced in application code. Rotating credentials or changing providers requires no code change.

**Structured output contract.** The gateway enforces that every model response conforms to the typed output schema expected by the calling agent. Raw unstructured text never reaches the clinical logic layer — schema validation failures are handled at the gateway boundary, not scattered through the application.

### Relationship to Clinical Agents

All three clinical agents — `AnalyzeClinicalRisks`, `MatchPolicy`, and `WriteNarrative` — route their inference calls through the gateway. They are authored against the typed contract; the gateway resolves which model fulfils it at runtime. This separation allows the active model to be changed without touching any agent definition.
