# 6.3 Comprehensive Audit Logging

To satisfy PDPA and HIPAA requirements for a clinical AI system, every AI inference operation and physician decision is captured in an immutable, cryptographically protected audit log. The log is written **synchronously before any recommendation response is delivered** — guaranteeing that no inference is ever unrecorded.

###5-Dimension Log Structure

Every audit entry is structured around five mandatory dimensions:

| Dimension | Fields Captured | Purpose |
|---|---|---|
| **Who** | `user_id`, `user_role` | Identity and role of the healthcare staff who triggered the inference (e.g., physician, nurse, pharmacist) |
| **When** | `timestamp` (ISO 8601, UTC) | Precise moment of the inference or clinical decision event |
| **Where** | `service_id`, `client_ip`, `request_id` | Originating service and network location of the request, enabling full source traceability |
| **What** | `scrubbed_ai_context` (full MCP context sent to the LLM, with PII removed), `ai_response`, `model_id`, `latency_ms`, `safety_conflict_events` | The complete transaction record of what was sent to the AI and what it returned. All patient-identifiable fields are **scrubbed before inference** — no PII reaches the AI or this log in any form |
| **Why** | `patient_id`, `action_type`, `request_id` | The clinical purpose that triggered the inference |

###Immutability: SHA-256 Hash Chaining

Immutability is enforced through cryptographic hash chaining. Each log entry computes:

```
current_hash = SHA-256(previous_entry_hash + current_payload)
```

The chain is anchored by a known genesis hash. Any post-write modification — including deletion, reordering, or content edits — produces a detectable hash mismatch across all subsequent entries. This provides tamper-evidence without requiring an external blockchain or notarization service.

###Physician Decision Logging

Approval and Rejection decisions by healthcare providers are recorded as a distinct event type. Each decision entry is linked to the original AI recommendation via a `recommendation_reference_hash`, creating a fully traceable audit trail:

```
Clinical Data → AI Inference → Human Review → Final Decision
```

###PII Enforcement

Patient-identifiable fields are **scrubbed entirely** from the clinical context before it is sent to the AI. The AI inference pipeline operates exclusively on de-identified clinical signals — no PII is substituted, tokenised, or rehydrated within the backend at any stage. Patient identity is resolved by the frontend from the `patient_id` at display time, using a secure lookup outside the AI pipeline.

###Retention

All audit records must be retained for a minimum of **3 years** per PDPA Section 40.
