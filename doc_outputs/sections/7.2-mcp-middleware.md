# 7.2 Model Context Protocol (MCP) Middleware

The Model Context Protocol (MCP) middleware layer sits between the clinical data platform and the AI inference pipeline. It exposes a standardised set of read-only tool interfaces that the AI agents use to retrieve structured patient context on demand. This section defines the **MCP → AI interface**: the tools, the clinical data they expose, and how each is consumed.

### Tool Interface

The MCP server exposes five read-only tools, each scoped to a single patient identified by `patient_token`. Four tools feed the AI inference pipeline; one feeds the clinical UI directly and is never sent to an LLM.

| Tool | Clinical Data Exposed | Consumer |
|---|---|---|
| `get_hard_constraints` | Patient demographics, active safety flags, eligibility exclusions, tier ceiling | AI inference — all 3 agents |
| `get_clinical_signals` | Fired signals, preliminary rule tier, overall risk level, missing signals, risk/comorbidity/screening flags | AI inference — all 3 agents |
| `get_biomarker_trends` | BMI, blood pressure, eGFR, lab values, ASCVD 10-year risk | AI inference — all 3 agents |
| `get_program_ruleset` | Tier selection rules, add-on item library, package resolution map | AI inference + deterministic rule evaluation |
| `get_patient_event_timeline` | Diagnoses, hospitalizations, screening history, medication changes | UI display only — **not sent to AI** |

### PII Scrubbing Gate

Before the assembled context from the four AI-facing tools is passed to any LLM, it passes through a PII scrubbing step. Patient-identifiable field values — including name, date of birth, phone, email, address, medical record number, and FHIR patient ID — are replaced with a neutral placeholder. The data structure is preserved; only the identifiable values are removed. No PII enters the AI inference pipeline or the audit log in any form.

### Design Constraints

- All tools are **read-only** — no tool writes to or modifies any clinical data store.
- Tool calls are **single-patient-scoped** — each call retrieves data for exactly one patient.
- The four AI-facing tools are called **in parallel** during Phase 1 of the workflow (see §7.1), with no ordering dependency between them.
- `get_patient_event_timeline` is called separately by the UI layer and is excluded from the AI context assembly.
